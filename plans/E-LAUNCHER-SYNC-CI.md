# Stage E — Launcher robustness + single-source sync + CI

## Goal

Make `launch.py` strict where it matters, end kernel↔notebook drift by
construction, and gate it all with CI that runs without Kaggle/TPU.

## Context

- `launch.py` decides push success by substring (`"successfully pushed"
  not in out`) and ignores `returncode`; cloning pulled metadata keeps
  `id_no` (Kaggle API footgun). Contracts the frozen Tauri app depends
  on must not break: serve/stop argv set, state-file keys, ntfy phases,
  `GET {endpoint}/v1/models`.
- Qwen notebook is hand-synced (drift is latent, not active); GLM
  notebook is generated by `tools/pack_notebook.py` (which currently only
  knows `glm53-flash`). References: PR #4 (tonyrishwain: `id_no` pop,
  returncode check — lift logic, not its notebook-template rewrite), PR
  #5 (check.yml, `sync_notebook.py --check`), PR #9
  (`tools/sync_notebooks.py` concept minus personal-draft generation).

## Work items

1. `launch.py`: `metadata.pop("id_no", None)` when cloning pulled
   metadata; set `enable_gpu/tpu/internet` explicitly; push check →
   `returncode != 0` first, case-insensitive substring, no `sys.exit` on
   benign output drift. Mirror in `cmd_build_env`. Keep ALL existing argv
   + state keys (Tauri contract).
2. `launch.py`: `save_state()` atomic + `0600`, `api_key_hint()`,
   `weights-progress` phase text, conditional `dataset_sources`
   (depends on Stage B — sequence after it).
3. Single-source sync tool: kernel(s) → notebook `%%writefile` cells,
   strip outputs/execution counts; must cover `qwen38-27b` AND
   `glm53-flash` (generalize `pack_notebook.py`, which is GLM-only today).
   `--check` mode for CI. No personal-draft generation (PR #9 lines
   rejected).
4. CI `.github/workflows/check.yml`: `py_compile`, `unittest discover`,
   sync `--check`, notebook JSON parse. Drop GPU-notebook legs (GPU path
   out of scope).
5. Regenerate both notebooks via the new tool; verify embedded cells
   match sources.
